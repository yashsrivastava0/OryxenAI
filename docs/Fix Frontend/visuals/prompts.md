# Image-generation prompts

Use the built-in image generation path, one image per prompt. These are `ui-mockup` references, not production artwork. Keep labels sparse and legible; the Markdown specification is authoritative for exact copy.

## 01-shell-overview.png

Use case: ui-mockup. Asset type: desktop product workspace reference. Show a serious agentic creative studio at 1536×695: warm paper background, deep ink typography, restrained cobalt accent, compact topbar, five-step stage navigator, one wide centered stage canvas, small context strip, visible sticky action dock, and a closed inspector affordance. One main surface only; no permanent left or right rail; no raw JSON visible. Avoid gradients, glassmorphism, dashboards, charts, fake percentages, and stock imagery.

## 02-discovery-intake.png

Use case: ui-mockup. Asset type: desktop Discovery intake reference. Show one focused intake field, concise explanatory copy, small prompt examples, word count, and one clear Start Discovery action inside a calm single-screen composition. Preserve generous whitespace without creating a scrollbar. Warm editorial Swiss styling, cream paper, ink, cobalt action. No JSON, utility rail, or oversized title.

## 03-discovery-review.png

Use case: ui-mockup. Asset type: desktop brief-review reference. Show compact brief title, status, short narrative summary, grouped profile facts, a collapsed full-brief reader, revision entry point, and a sticky bottom action dock with Approve and Revise. The action must be visible without a long document scroll. No six-line title, no raw JSON.

## 04-content-route-review.png

Use case: ui-mockup. Asset type: desktop content architecture reference. Show a route map across the top, accessible route tabs, one selected route, section cards with real-looking concise copy, a narrative thesis, and a visible approval/revision action dock. Use purposeful asymmetry but keep the text column readable. Do not show every route expanded simultaneously.

## 05-design-storyboard.png

Use case: ui-mockup. Asset type: desktop visual direction reference. Show creative thesis, prose intent cards for color behavior, typography behavior, motion, and interaction, then a visible numbered scene storyboard with route selector. Use neutral intent language; do not show hex colors, color swatches, font names, CSS values, or external images.

## 06-preparation-ready.png

Use case: ui-mockup. Asset type: desktop Build Preparation handoff reference. Show readiness status, compact route/section/resource/component counts, metadata evidence tiles with source/license/dimensions, two collapsed brief readers, and a visible Continue to Generate action. Use neutral placeholder evidence blocks instead of broken images or keyword alt strings.

## 07-generation-available.png

## 09-generation-attention.png

Use case: ui-mockup. Asset type: desktop failure-recovery reference. Make the error calm and actionable, not alarming or vague.

## 10-mobile-review.png

Use case: ui-mockup. Asset type: mobile review reference at 390×844. Show compact topbar, current-stage selector, one-column artifact, route tabs contained in their own strip, readable cards, and a full-width reserved action dock. No horizontal page overflow, clipped labels, permanent rails, or decorative margin text.

## 11-output-inspector.png

Use case: ui-mockup. Asset type: developer-only inspector reference. Show the normal single-canvas product surface with a slide-over Output Inspector opened explicitly. The drawer contains selected stage label, safe status metadata, formatted read-only JSON, and a copy action. Keep it visually subordinate and clearly separate from the creator artifact. No secrets, prompts, raw worker payloads, or model reasoning.

## 12-admin-control-center.png

Intended viewport: 1536×695. Use case: ui-mockup. Asset type: administrator-only desktop product reference. Show a serious OryxenAI workspace administration surface using warm cream paper, deep ink typography, restrained cobalt accents, hairline rules, a compact topbar, administrator identity, Workspace/Refresh/Sign out controls, a live status line, safe account details, a six-tab list (`Users`, `Projects`, `Legacy`, `Deleted`, `Operations`, `Audit`), four summary metrics (`Active users`, `Projects`, `Running jobs`, `Pending operations`), and a clean Users ledger with masked metadata and compact lifecycle buttons (`suspend`, `reset entitlement`, `promote`, `delete`) plus `Load more`. Keep destructive buttons subordinate and make the screen read as a bounded ledger, not a creator stage. No creator stage navigator, raw JSON, external images, secrets, UUIDs, charts, fake percentage dials, stock photography, or permanent developer rail. This is a reference only; exact counts, names, timestamps, authorization, and action results come from the existing admin API and Markdown contract.
