# Raw Build Preparation brief compatibility dispatch

This change adds dual-format admission: historical route-local section IDs are canonicalized, while namespaced briefs remain a compatibility format. The fail-closed boundary is incomplete because version and candidate data can bypass the new shape checks, and resource ownership is lossy. Namespaced inputs can also be rejected or recompile to different projections without changing admitted identity. Watch for: **HIGH · confirmed** version/dependency smuggling, **HIGH · confirmed** multi-route ownership loss, and **HIGH · confirmed** projection drift across resume.

**Verdict**: NEEDS_CHANGES

## High-level view

**HIGH · confirmed:** Duplicate JSON keys are resolved last-wins before declaration checks. **MEDIUM · confirmed:** The raw fallback also accepts coercible values outside the historical wire shape; its structural signature does not gate dispatch.

**HIGH · confirmed:** Candidate and suggestion dictionaries bypass unknown-field validation, allowing undeclared dependency metadata to reach acquisition.

**HIGH · confirmed:** Build Preparation permits plural route ownership, but Code Generator silently binds each resource to only the first route.

**HIGH · confirmed:** The new local-section matcher changes some namespaced projections without changing admitted identity, and resume does not compare recompiled projection hashes with the stored receipt.

**MEDIUM · confirmed:** Previously accepted namespaced version declarations now map only to raw input, while Build Preparation labels any `RouteScope` as raw v1 without validating its section-ID style.

**MEDIUM · confirmed:** Unversioned compatibility admission and declared raw-v1 admission receive the same version, format, and structural-signature metadata, hiding which dispatch path was used.

<details><summary>Details</summary>

## Duplicate version keys bypass conflict rejection — HIGH · confirmed

`_tagged_index` uses ordinary `json.loads` at `src/oryxenai/agents/code_generator/core/brief_ingestion.py:487`, which retains the last duplicate key. `_declared_source_version` checks only the resulting dictionary at `brief_ingestion.py:615-637`. A pair containing `"brief_contract_version": "future-v9"` followed by the supported value compiles as raw v1, while a first-key-wins consumer sees an unsupported contract. Reject duplicate keys recursively before dispatch and cover duplicates in version, route, navigation, resource, and candidate objects.

## Raw fallback accepts non-historical wire values — MEDIUM · confirmed

`_validate_wire_shape` restricts key names but not exact required fields or strict types (`brief_ingestion.py:577-603`). Later `str()` coercion admits numeric route IDs and matching numeric navigation/visual-route references as string IDs (`brief_ingestion.py:659-725,840-897`). The structural signature is computed only after format selection and is never used as an admission predicate (`brief_ingestion.py:564`). Use strict per-format wire models with exact required keys, non-coercing types, and forbidden extras before allowing the unversioned exception.

## Candidate fields can smuggle dependency requests — HIGH · confirmed

The new allowlist stops at each resource/component entry (`brief_ingestion.py:577-603`), leaving candidate and suggestion dictionaries open. `_resolution` copies undeclared `dependencies` and `registry_dependencies` into the execution contract (`brief_ingestion.py:1193-1209`), and acquisition turns them into dependency metadata and requests (`src/oryxenai/jobs/handlers/code_generator.py:1911-1998`). The package allowlist limits installation, but the brief can request configured packages outside the producer schema. Validate nested candidates against strict Build Preparation schemas and derive component dependencies from the fetched pinned registry response instead.

## Multi-route ownership is truncated — HIGH · confirmed

Build Preparation models `route_ids` as a list and can emit multiple owners (`src/oryxenai/agents/build_preparation/schemas.py:254,269`; `src/oryxenai/agents/build_preparation/compiler.py:389,481`). Code Generator validates all listed routes, then selects `route_ids[0]` and derives bindings only from that route (`brief_ingestion.py:1064-1071`). A font owned by `home` and `work` becomes one `home` slot, dropping all `work` section and criterion bindings. Reject plural ownership as unsupported or expand it deterministically into per-route slots with complete criteria.

## Namespaced projections drift under a stable identity — HIGH · confirmed

`_role_sections` now strips the route namespace for every format (`brief_ingestion.py:1220-1228`). For a previously admissible namespaced section `home:hero` and role `assumed-image:hero:0`, the old projection had no section binding and the new projection binds `home:hero`; the contract/admitted identity remains unchanged while `execution/contract.json` gets a different projection hash (`brief_ingestion.py:426-444`). Resume re-admits the source and combines those projections with the persisted plan without checking stored projection hashes (`src/oryxenai/agents/code_generator/core/generation_orchestrator.py:819-846`). Preserve the prior matcher for namespaced format, or version the compiled identity and fail resume on projection-hash drift.

## Namespaced version continuity breaks both directions — MEDIUM · confirmed

The dispatcher maps `build-preparation-brief-v1` exclusively to raw IDs and introduces a new namespaced version (`brief_ingestion.py:23-25,518-535`), so namespaced briefs carrying the previously supported declaration now fail re-admission. Build Preparation also writes raw v1 unconditionally (`src/oryxenai/agents/build_preparation/brief_assembly.py:57,194`) although `RouteScope.section_ids` accepts namespaced strings (`src/oryxenai/agents/build_preparation/schemas.py:58-67`); reassembling `home:hero` emits a pair Code Generator rejects. Add an explicit legacy namespaced migration/dispatch and validate or select the producer declaration from the actual ID format.

## Compatibility downgrade is absent from provenance — MEDIUM · confirmed

Unversioned raw input is assigned the declared raw-v1 version and format (`brief_ingestion.py:537-541`). Because structural signatures exclude version keys (`brief_ingestion.py:748-751`), stripping both declarations leaves the same version, format, and signature metadata. Record a `legacy_unversioned` versus `declared` dispatch mode in receipt provenance and resume diagnostics.
