# Durable retry epochs and immutable generation continuation

All five prior findings are closed in their original paths: explicit retry now advances model identity, pending proposals retain crash-safe predecessors, request receipts survive retries, checkpointed owners lose transient polish state, and same-epoch integration-review replay deduplicates. One new blocker remains in the interaction between explicit epochs and integration-review deduplication. A fresh review call still uses its epoch-zero receipt identity, so it either collides with preserved history or is incorrectly recorded as the old call.

Watch for: **[confirmed, P1] explicit integration-review retries colliding with or disappearing into an earlier epoch's call receipt**.

**Verdict**: NEEDS_CHANGES

## High-level view

Prior finding 1 is **CLOSED**. Explicit retry durably increments `attempt_epoch`; generation cache and attempt identities include it, while automatic redelivery retains the existing epoch.

Prior finding 2 is **CLOSED**. Proposal successors are content-addressed and written before projection replacement, and predecessor cleanup follows persisted acceptance for ordinary units, serial route units, and integration polish.

Prior finding 3 is **CLOSED**. Request receipt IDs survive explicit retry, and legacy `acquiring` state consumes one already-counted transition credit rather than incrementing the aggregate again.

Prior finding 4 is **CLOSED**. Every work unit, including checkpointed polish owners, loses transient request/proposal/repair state while checkpoint status, hashes, and immutable receipt history remain intact.

Prior finding 5 is **CLOSED as originally raised**: context, call, and attempt records deduplicate same-epoch review redelivery. The new issue is that call-receipt identity also deduplicates across explicit epochs, where the call is no longer the same logical attempt.

## Whole-site review receipts collapse distinct explicit attempts

**[confirmed, P1]** Review attempt records are epoch-scoped through `_reserve_generation_attempt` (`generation_orchestrator.py:555-578`, `:2580-2589`), but the associated call receipt uses only the context hash for `receipt_id` and only generation, operation, and round for `idempotency_key` (`generation_orchestrator.py:2634-2651`). Explicit integration retry always starts at round zero (`generation_orchestrator.py:2125-2137`), so retrying unchanged accepted source recreates that identity while performing a fresh provider call. `_record_call_receipt` then rejects a changed review hash as `GENERATION_CALL_RECEIPT_COLLISION`; if the hash matches, it suppresses the new receipt and makes the new epoch's attempt point to the old call (`generation_orchestrator.py:223-243`).

Derive the review call ID from `_generation_attempt_namespace(...)`, review round, and context hash. This retains same-epoch redelivery deduplication and gives explicit retry a distinct call receipt aligned with its distinct attempt record. The current regression covers two same-epoch calls with identical output (`tests/unit/agents/code_generator/test_semantic_decline_reliability.py:786-855`); add an incremented-epoch case with a different valid review and assert two call receipts and two attempt records.

</details>
